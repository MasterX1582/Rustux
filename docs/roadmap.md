# Roadmap: a Linux-compatible kernel in Rust

Goal: a drop-in replacement for the Linux kernel — same syscall ABI, same
behavior — built unit by unit, each verified against the original C code's
recorded behavior before adoption.

## Method (per unit)

1. Extract the C unit into `ports/<unit>/` with the smallest shim that makes it
   compile as a userspace shared library (`tools/lib` and `tools/testing`
   provide pre-shimmed copies of many kernel data structures).
2. `rust-anything bridge <harness-dir> <unit>` — generates a Rust crate with
   the same `extern "C"` API.
3. `rust-anything record <crate>` — runs the original C on edge cases, saves
   `cases.jsonl`. Add real-world inputs with `--inputs` when needed.
4. Write `src/port.rs`. Iterate `build`/`diff` until every recorded case
   matches. `gate` must pass: no `unwrap`/`panic` where the original returns
   errors, no `unsafe` without `// SAFETY:`, fmt+clippy clean.
5. Adopt the verified logic into `kernel/src/` adapted to `no_std`. The
   verification crate keeps the original API forever as the regression suite.
6. Stop, report, get approval for the next unit (rust-anything's rule).

## Waves

### Wave 0 — freestanding algorithms (now)

`lib/` + `crypto/` + `tools/lib`. Everything uses these; they use nothing.
rust-anything's record/diff works almost directly — the strongest possible
verification. ~680 files, ~380k lines.

`lib/math` is now **fully ported** (all 11 units). Done so far (adopted into
`klib::math`, all gates passed):
`int_sqrt` (17/17), `gcd` (154/154), `lcm`+`lcm_not_zero` (308/308),
`int_pow` (154/154), `intlog2`+`intlog10` (34/34),
`mul_u64_add_u64_div_u64` (232/232), `iter_div_u64_rem` (custom pointer-arg
check `ports/lib-math/check-iter-div.py`, 72/72 — rust-anything's ctypes
bridge can't take pointer args; document each such case or write a custom
check like it),
`rational_best_approximation` + `reciprocal_value` + `reciprocal_value_adv` +
`cordic_calc_iq` + `polynomial_calc` (1448/1448 via scalar-field wrappers —
`ports/lib-math/wrappers.c` converts struct out-params into scalar returns so
the standard record/diff pipeline verifies the real functions transitively).
`verify-all.sh` re-runs every crate's diff+gate plus the pointer-arg check.
`is_prime_number`/`next_prime_number`/`slow_is_prime_number` (57/57 via
single-threaded mutex/RCU/slab/bitmap shims; klib uses a fixed-capacity
static sieve whose exhaustion plays the `kmalloc`-failure role).

`lib/` core utils (adopted into `klib::{bcd,sort,list_sort}`, gates passed):
`bcd2bin`/`bin2bcd` (34/34), `sort`/`sort_r`/`sort_nonatomic` and `list_sort`
(763/763 via scalar wrappers — `ports/lib-core/wrappers.c` drives
deterministic seeded arrays/lists through the real C functions and returns
order-sensitive checksums/elements). `list_sort` is ported over an
index-linked `Links{next,prev}` model (NIL = NULL, sentinel head index);
`sort` is the `__sort_r` bottom-up heapsort over element indices — the C's
byte-offset/`lsbit` parent trick reduces to `(k-1)/2` for every element size.

`lib/crc` (adopted into `klib::crc`, gates passed): every arch-neutral CRC
unit — `crc32_le`/`crc32_be`/`crc32c`, `crc64_be`/`crc64_nvme`, `crc16`,
`crc_ccitt`, `crc_itu_t`, `crc7_be`, `crc_t10dif_update`,
`crc8`+`crc8_populate_{msb,lsb}` (2666/2666 via seeded-buffer wrappers —
the buffer-arg functions verify transitively), `crc4` (222/222 direct).
Lookup tables are regenerated by const fns mirroring the kernel's own
`gen_crc*table.c` — the recorded diff proves them identical. `crc4`'s
recorded corpus included out-of-contract inputs (`c`>15 indexes past the
16-entry table — layout-dependent UB); the corpus was curated to the
contract domain and the divergence documented.

`lib/crypto/siphash.c` + `lib/xxhash.c` + `include/linux/jhash.h` (adopted
into `klib::hash`, gate passed): SipHash2-4 and the LP64 "hsiphash"
(SipHash1-3 keyed on `unsigned long[2]`), all `siphash_*u32/u64` scalar
variants, xxh32/xxh64 one-shot plus the `xxh64_reset/update/digest`
streaming API driven through chunked updates (mem64 residue paths), and
the jhash header family — 5020/5020 recorded cases. Both
`__siphash_{aligned,unaligned}` backends are exercised by controlling
wrapper-buffer alignment (they are byte-identical algorithms, so the
port/klib share one implementation); `CONFIG_DCACHE_WORD_ACCESS` and
`CONFIG_HAVE_EFFICIENT_UNALIGNED_ACCESS` are left undefined, matching the
portable upstream path.

Harness notes learned along the way: kernel typedefs must be normalized to
stdint names (`u64`→`uint64_t`) for the bridge's scalar map; functions inside
`#if` regions are invisible to the export scanner (pre-resolve branches for
the target config); `linux/types.h` carries a harness-wide LP64 `#error`
guard; crash records count as "UB — anything passes" so trap-on-input cases
are documented divergences, not verified behavior.

`lib/find_bit.c` + `lib/bitmap.c` + the `include/linux/{bitmap,find}.h`
inline layer + the generic `unsigned long` bitops surface (adopted into
`klib::{bitmap,bitops}`, gate passed): all 15 `_find_*`/`find_*` finders
including nth/and/andnot/or/zero/wrap/le-alias variants, `find_next_clump8`,
`find_random_bit` (harness RNG is a deterministic splitmix64 since upstream
is a CSPRNG; klib takes the draw as a caller `FnMut`), the `for_each_*`
iteration layer, every `__bitmap_*`/`bitmap_*` logic op (and/or/xor/andnot/
replace/complement/equal/or_equal/intersects/subset/weight family/weighted
ops/set/clear/shift/cut/zero-area/find_free_region/remap/bitremap/onto/
fold/scatter/gather/read/write/{get,set}_value8/arr32+arr64 conversion) —
30915/30915 recorded cases over 147 scalar wrappers, including `_c`
constant-size variants covering the `small_const_nbits` fast paths, the
GENMASK/memcmp/single-word inlines, and `CONFIG_NUMA`'s `bitmap_onto`/
`bitmap_fold`. `bitmap_{alloc,zalloc,free,devm_*}` are kmalloc glue that
lands with the allocator port (wave 1); `bitmap_parse*` belongs to
`lib/bitmap-str.c`, a separate future unit.

`lib/rbtree.c` + `include/linux/{rbtree,rbtree_types,rbtree_augmented}.h`
done (1811/1811 differential cases + 40-seed RB-invariant selftest, gate
passed): index-pool model where `RbNode::pc` packs parent|color exactly like
`__rb_parent_color`; insertion, `__rb_erase_color` rebalancing, traversal,
cached roots, linked nodes, postorder, `rb_find*`/`rb_find_add*`/`rb_add*`
search helpers, and the full `rb_augment_callbacks` surface (subtree-max
verified). Adopted as `klib::rbtree` over caller-owned `&mut [RbNode]` pools
with `Link{Root,Left(i),Right(i)}` modeling C's `struct rb_node **` and
`impl Fn` comparators capturing user payload. RCU variants alias the plain
paths (no RCU semantics in klib yet). Remaining thin surface for a later
pass: `rbtree_postorder_for_each_entry_safe`/`rb_entry_safe` macros,
`RB_EMPTY_ROOT` inline (trivial), multi-field `RB_DECLARE_CALLBACKS`.

`lib/string.c` done (8038/8038 differential cases, gate passed): all 34
functions — case-insensitive compares, strcpy/stpcpy/strcat/strncat/strlcat,
`sized_strscpy` (all three return classes incl. `-E2BIG`), strcmp/strncmp
(kernel sign-normalized `±1`, not glibc byte-diffs), the chr/len/spn/pbrk/
strsep finders, memset{,16,32,64}/memcpy/memmove/memcmp/bcmp, memscan,
strstr/strnstr, memchr, and word-at-a-time `memchr_inv`. Adopted as
`klib::string` — `&[u8]` slices + `usize` offsets, NULL→`Option<usize>`,
scan-for-NUL functions panic on unterminated slices (bounded, where C
over-reads). Harness needed glibc-symbol hiding (hidden-visibility
prototypes) plus `#undef __BIG_ENDIAN` after glibc's endian.h.

`lib/crypto/sha*.c` done (6174/6174 differential cases, gate passed):
SHA-1/224/256/384/512 block transforms, init/update/final, one-shots,
`sha256_finup_2x` (generic sequential), the full HMAC family
(preparekey/init/update/final, raw-key + prepared-key paths, >blocksize
key hashing), and the `*_zero_message_hash` published consts. Adopted as
`klib::sha` — C-faithful ctx structs (`Sha1Ctx`, `__Sha256Ctx`/`Sha256Ctx`,
`__Sha512Ctx`/`Sha512Ctx`, `HmacSha*Key`/`HmacSha*Ctx`), `Option<&ctx>`
for finup_2x's NULL ctx, `core::ptr::eq` mirroring C's `iv == &sha224_iv`
address compare. Note: the freestanding units are `lib/crypto/sha*.c`;
`crypto/sha*.c` is the shash registration glue for a later wave.

`lib/kfifo.c` done (960/960 differential cases, gate passed): the full
`__kfifo_*` surface — init/alloc, in/out/peek/linear, user-copy paths,
DMA scatterlist prepare/finish, and the record variants (`*_r`,
recsize 0/1/2) — plus the `kfifo.h` arithmetic helpers. Adopted as
`klib::kfifo`: `Kfifo<'a>` borrows the caller's backing buffer (NULL
`data` unrepresentable; EINVAL→`Err`), `u32` wraparound counters
preserved, `Sg` entries carry offsets into `fifo.data`. The typed
`STRUCT_KFIFO` macro layer is C-generic sugar — Rust callers get type
safety from the borrow model directly.

Wave 0 (freestanding algorithms) complete. Next: Wave 1 kernel data
structures — xarray/idr/radix-tree/maple-tree, rhashtable, llist,
`tools/testing/*` harnesses.

### Wave 1 — kernel data structures (test harnesses exist)

xarray/idr/radix-tree/maple-tree, rhashtable, percpu counter logic, llist,
kfifo ring, printk ringbuffer, seq_buf. `tools/testing/{radix-tree,maple,vma,bitmap}`
already builds them in userspace — record against those harnesses.
~100 units, most of `lib/` + key `mm/` internals.

Done: `lib/llist.c`+`llist.h` (531 cases) → `klib::llist` index-model
(atomics sequential); `lib/seq_buf.c`+`seq_buf.h` (599 cases) →
`klib::seqbuf` + `klib::fmt` interim mini-vsnprintf (real printf lands
with `lib/vsprintf.c`). Skipped: seq_buf_print_seq/path/bprintf
(seq_file/d_path/CONFIG_BINARY_PRINTF deps).
`lib/rhashtable.c`+`rhashtable.h`+`bucket_locks.c` (1111 cases) →
`klib::rhashtable`: caller-owned `&mut [u64]` dense arena, canonical
addresses via `idx()`, locks/RCU/workqueues sequential, rhltable
chains, nested-table alloc fallback, walk API, `fail_nth` injection.
In progress: `lib/xarray.c` port (wrap_xa_multi diffs outstanding).

### Wave 2 — core services (custom shims needed)

Timer wheels, workqueues, sched policy math (deadline calc, fair scheduling
decisions), slab allocator internals, buddy allocator, waitqueues, futex hash
logic. Each needs a hand-written userspace shim exposing the unit's contract;
record/diff still applies to the algorithmic core. ~2k files (`kernel/`+`mm/`).

### Wave 3 — kernel core & ABI (verification shifts to differential testing)

Entry/exit, interrupts, context switch, page tables, syscall dispatch, VFS,
ELF loader, signals. Not unit-recordable — verify by booting the same
initramfs workload under both kernels and diffing observable behavior
(serial log, syscall traces via a test suite like LTP). ~4k files.

### Wave 4 — drivers & stacks

Per-device/conformance. Start with virtio (mmio/blk/net/console — QEMU gives
us free test hardware), then storage/display/input. GPU drivers are ~5M LOC of
the tree and last. `net/`+`fs/` per-protocol, per-filesystem. ~25k files.

### Wave 5 — drop-in parity

Full syscall surface vs `man-pages`/kernel selftests + LTP, `/proc`+`/sys`
compat, modules vs fixed ABI decision, userspace distro boot.

## Notes

- Reference designs worth studying: **Asterinas** (Rust framekernel, already
  Linux-ABI compatible), **Maestro**, and upstream **Rust for Linux**
  (`rust/` in the C tree — abstractions we can mirror).
- The kernel skeleton boots UEFI today; when it grows past a single binary,
  switch to a Limine-booted ELF kernel + initramfs (needed for wave-3
  differential testing anyway).
- `unsafe` policy: allowed only at hardware boundaries (port I/O, MMIO, paging,
  context switch), always with `// SAFETY:` comments — same bar `gate` enforces.
